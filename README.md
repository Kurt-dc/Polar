# Polar Holter (native Android, Kotlin) — MVP-каркас

Нативный Android-проект, выросший из веб-версии (`polar-hrv-analyzer` PWA).
Главная причина переезда на native: **Web Bluetooth не может держать
соединение при выключенном экране/свёрнутой вкладке** — на Android это
делает только `Foreground Service`, недоступный из браузера.

## Что уже реализовано

- `ble/PolarBleManager.kt` — подключение к Polar H10, тот же протокол PMD
  (UUID `fb005c80/81/82-...`), что и в веб-версии: запуск ECG-потока,
  разбор 24-битных кадров, стандартный Heart Rate Service как fallback.
- `service/RecordingService.kt` — `Foreground Service` с `WakeLock`,
  который держит BLE-соединение и запись живыми при выключенном экране.
  Пишет сырые отсчёты в CSV в `filesDir/sessions/`.
- `analysis/EcgAnalyzer.kt` — детекция R-зубцов, оценка ЧСС и ширины QRS,
  флаги подозрительных участков (нерегулярный ритм, паузы, тахи/брадикардия,
  широкий QRS, плохое качество сигнала). **Сознательно не ставит диагнозы**
  и не определяет ЭОС — см. комментарий в начале файла, почему это
  технически невозможно на одном отведении.
- `ui/MainActivity.kt` — Compose UI: скан устройств, старт/стоп записи,
  запрос на исключение из оптимизации батареи (нужно на Xiaomi/Huawei/Samsung,
  которые агрессивно убивают фоновые сервисы даже с `Foreground Service`).

## Changelog — исправления после ревизии кода

При повторной проверке (после того, как сборка стала проходить в CI)
нашлись реальные баги в коде, не связанные с настройкой сборки:

1. **`AndroidManifest.xml` ссылался на несуществующую иконку**
   `@mipmap/ic_launcher` — в проекте не было ни одного mipmap-ресурса,
   сборка гарантированно падала бы на этапе AAPT. Добавлена простая
   векторная иконка `res/drawable/ic_launcher.xml`, манифест указывает на неё.
2. **Краш на Android 8.0/8.1** — `startForeground(id, notification, type)`
   с третьим аргументом появился в API 29, а `minSdk` проекта — 26.
   На Android 8.x вызов падал бы с `NoSuchMethodError`. Добавлен
   `startForegroundCompat()` с веткой по версии.
3. **ЭКГ и ЧСС молча не доходили на Android до 13** — `onCharacteristicChanged`
   с явным `value` (новая сигнатура) существует только с API 33; на более
   старых версиях система вызывает старый двухаргументный колбэк, который
   не был переопределён — данные просто терялись без единой ошибки в логах.
   Добавлены обе версии колбэка + `writeCharacteristicCompat` /
   `writeDescriptorCompat` для тех же версий API записи характеристик.
4. **`EcgAnalyzer.reset()` не сбрасывал детектор локального пика** —
   после сброса анализатора (при каждом старте новой записи) могла
   сработать ложная пометка на основе состояния от предыдущей сессии.
5. Мелочи: неверное место объявления `xmlns:tools` в манифесте, лишние
   неиспользуемые импорты.

## Как собрать

1. Открыть папку `PolarHolter/` в Android Studio (Koala или новее).
2. Дать Android Studio сгенерировать `gradle-wrapper.jar` при первом синке
   (в архиве его нет — бинарник, задаётся автоматически через
   `gradle-wrapper.properties`), либо выполнить `gradle wrapper` локально
   при наличии установленного Gradle.
3. Собрать и установить на телефон с Android 8.0+ (minSdk 26 — минимум для
   стабильного BLE + foreground service; Polar H10 сам требует BLE).

## Важные ограничения, которые НЕ стоит "чинить" тихо

- **Это не 24-часовой холтер.** Polar H10 в режиме потоковой ECG садится
  заметно быстрее, чем в режиме обычного пульсометра. Реалистичный сценарий —
  несколько часов на заряде/подключённом телефоне. В UI это должно быть
  написано прямо, а не подразумеваться.
- **Некоторые прошивки Android всё равно убивают сервис** (агрессивные
  политики энергосбережения MIUI/EMUI/One UI), несмотря на
  `Foreground Service` + исключение из battery optimization. Нужно
  тестировать на реальных устройствах целевых пользователей.
- **Флаги — не диагноз.** Формулировки в `EcgAnalyzer` намеренно
  осторожные ("возможно", "для оценки врачом"). Если в будущем добавлять
  более сложные алгоритмы (например, детекцию фибрилляции предсердий по
  вариабельности R-R), сохраняйте тот же принцип: помечать участок для
  просмотра, а не заявлять диагноз.
